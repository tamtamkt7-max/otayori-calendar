# おたよりカレンダー (Otayori Calendar) 🚀

園や学校から容赦なく配布されるプリント類や、LINE/メールで送られてくるスクリーンショットをスマートフォンのカメラで撮影するだけで、AI（Gemini 3.5/1.5 Flash）が自動で日時・持ち物・イベント名を高度に構造化データに変換し、アプリ内のカレンダーへ即時自動登録する子育て世代向けWeb/PWAアプリケーション。

将来的なネイティブスマホアプリ（iOS/Android）環境へのスムーズな移行・連携を絶対の前提とした、APIファースト設計で構築されています。

---

## 💰 収益化・原価防御ロジック（赤字絶対回避システム）

- **フリーミアムモデルを採用:**
  - **無料ユーザー:** 画面下部にWeb広告を表示。AI自動スキャンはサーバーサイド（Firestore）で厳密に制御され、**月間10回**に制限。これを超えた瞬間に403エラーでAPIコールを物理遮断し、APIコストの予期せぬ高騰を防ぎます（API破産防御のセキュリティ壁）。
  - **月額プレミアムユーザー（想定: 480円/月）:** 広告の完全非表示、AI自動スキャン制限の解除、パートナーとのカレンダーリアルタイム家族同期共有。
- **AI原価の最小化:** 画像認識およびテキスト構造化のエンジンとして、極めて高速かつ安価な `Gemini 3.5 Flash` を採用。サブスクリプション売上および広告収入が、API消費コストを完全にアウトパフォームする設計を維持しています。

## 🛠 本番用堅牢化 & 拡張機能 (追加機能)

本番環境の長期的な安定運用とセキュリティ、およびユーザー体験の向上のため、以下の機能を実装しています。

### 1. エラー監視・リアルタイム検知 (Sentry)
- **構成**: `@sentry/nextjs` によるフルスタックエラー追跡。
- **アーキテクチャ**:
  - APIルート (`/api/scan`, `/api/events`, `/api/webhook/stripe`) 内での例外をキャッチし、自動的にSentryサーバーに例外イベントを送信。
  - 本番環境でのサーバークラッシュ、Stripe署名検証失敗、Gemini APIのクォータ切れなどをリアルタイムで自動検知・通知します。

### 2. 自動メール通知 (Resend)
- **構成**: `resend` SDKを使用したトランザクショナルメール送信。
- **アーキテクチャ**:
  - Stripeの Webhook イベントを受け取り、プラン変更完了時に自動でメールを送信します。
  - **決済・アップグレード完了時**: プレミアムプランの特典紹介を含むウェルカムメールの送信。
  - **サブスクリプション解約完了時**: 解約処理が正常に行われたことを通知するメールの送信。
  - 送信先アドレスは、Stripe Checkoutに入力された最新のクライアントアドレス、またはStripe APIから直接取得した顧客データを元にします。

### 3. APIセキュリティ強化 (Firestore レートリミット)
- **構成**: Firestoreの書き込み履歴を活用したスライディングウィンドウ型レートリミッター。
- **アーキテクチャ**:
  - 不正スクリプトやDDoS攻撃、二重クリック防止のため、各重要APIルートでアクセス制限を実施。
  - **Checkout API**: 1分間に最大3回まで。
  - **AI Scan API**: 1分間に最大5回、1日に最大30回まで。
  - **Events API (保存・削除)**: 1分間に最大15回、1日に最大100回まで。
  - 制限を超過した場合は自動的に `HTTP 429 Too Many Requests` エラーを返却し、バックエンドのシステム負荷を防御します。

### 4. カレンダーUIの改善 (レスポンシブ刷新 & 週・月表示切り替え)
- **構成**: Tailwind CSS + Lucide React によるフルレスポンシブ設計。
- **機能**:
  - PC、スマホ、タブレットに完全対応したレイアウト。
  - 月カレンダーと週カレンダー（現在の選択日の週を7日分表示）の表示切り替えトグルの追加。
  - 予定の有無と予定登録者のカラー（パパ・ママ・子供など）に合わせた美しく整列するカラーバッジ。
  - スキャン実行時の高級感あふれるローディング・スケルトンアニメーション。

### 5. Google カレンダー双方向同期 (OAuth 2.0)
- **構成**: `googleapis` (Google Calendar API v3) + OAuth 2.0 認証フロー。
- **アーキテクチャ**:
  - アプリから「Google連携」ボタンを押し、Googleカレンダーの編集権限を承認。
  - 認可コードから取得したリフレッシュトークン等の認証情報を、セキュアなAES-256-CBC方式で暗号化してFirestore (`users/${userId}/security/googleOAuth`) に格納。
  - ユーザーがアプリ上でおたよりをスキャンして予定が保存、または手動で予定を作成・変更・削除した際、自動的にバックエンドでトークンの有効期限をチェック（必要に応じてリフレッシュトークンで自動更新）し、ユーザーのGoogleカレンダーに予定をシームレスかつリアルタイムに同期します。
  - 予定には `googleEventId` が紐づけられ、編集・削除時も同一イベントが追跡更新されます。

## 🔑 Google OAuth 2.0 設定手順 (管理者向け)

カレンダー連携機能を使用するためには、Google Cloud ConsoleでのOAuthクライアントIDの設定が必要です。

1. **Google Cloud Console** にログインし、新しいプロジェクトを作成または既存のプロジェクトを選択します。
2. **「APIとサービス」 > 「ライブラリ」** から、**Google Calendar API** を検索し、「有効にする」をクリックします。
3. **「OAuth同意画面」** を設定します：
   - User Type: 外部 (External)
   - スコープに `.../auth/calendar.events` (カレンダーの予定の表示・編集) を追加します。
   - テストユーザーにテスト用のGoogleアカウントを追加しておきます。
4. **「認証情報」 > 「認証情報を作成」 > 「OAuthクライアントID」** をクリックします：
   - アプリケーションの種類: Webアプリケーション
   - **承認されたリダイレクトURI** に、以下の本番コールバックURLを追加します：
     `https://<your-vercel-domain>.vercel.app/api/auth/google-calendar/callback`
     （ローカル開発時は `http://localhost:3000/api/auth/google-calendar/callback` も併記可能）
5. 生成された **クライアントID** と **クライアントシークレット** を、環境変数 `GOOGLE_CLIENT_ID` および `GOOGLE_CLIENT_SECRET` に設定します。
6. 暗号化用のキーとして、`ENCRYPTION_KEY` に十分な長さ（32文字以上推奨）のランダムな文字列を設定してください。

## 📦 ローカル環境構築およびテスト手順

### 1. 依存パッケージのインストール
```bash
npm install
```

### 2. 環境変数の設定
`.env.example` をコピーして `.env.local` を作成し、各種キーを設定します。

### 3. アプリケーションのビルドと実行
```bash
# 開発サーバー起動
npm run dev

# プロダクションビルド確認
npm run build
```
