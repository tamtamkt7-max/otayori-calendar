# おたよりカレンダー (Otayori Calendar) 🚀

園や学校から容赦なく配布されるプリント類や、LINE/メールで送られてくるスクリーンショットをスマートフォンのカメラで撮影するだけで、AI（Gemini 3.5/1.5 Flash）が自動で日時・持ち物・イベント名を高度に構造化データに変換し、アプリ内のカレンダーへ即時自動登録する子育て世代向けWeb/PWAアプリケーション。

将来的なネイティブスマホアプリ（iOS/Android）環境へのスムーズな移行・連携を絶対の前提とした、APIファースト設計で構築されています。

---

## 💰 収益化・原価防御ロジック（赤字絶対回避システム）

- **フリーミアムモデルを採用:**
  - **無料ユーザー:** 画面下部にWeb広告を表示。AI自動スキャンはサーバーサイド（Firestore）で厳密に制御され、**月間10回**に制限。これを超えた瞬間に403エラーでAPIコールを物理遮断し、APIコストの予期せぬ高騰を防ぎます（API破産防御のセキュリティ壁）。
  - **月額プレミアムユーザー（想定: 480円/月）:** 広告の完全非表示、AI自動スキャン制限の解除、パートナーとのカレンダーリアルタイム家族同期共有。
- **AI原価の最小化:** 画像認識およびテキスト構造化のエンジンとして、極めて高速かつ安価な `Gemini 3.5 Flash` を採用。サブスクリプション売上および広告収入が、API消費コストを完全にアウトパフォームする設計を維持しています。

## 🛠 本番用堅牢化 & 拡張機能 (追加機能)

本番環境の長期的な安定運用とセキュリティ、およびユーザー体験の向上のため、以下の機能を実装しています。

### 1. エラー監視・リアルタイム検知 (Sentry)
- **構成**: `@sentry/nextjs` によるフルスタックエラー追跡。
- **アーキテクチャ**:
  - APIルート (`/api/scan`, `/api/events`, `/api/webhook/stripe`) 内での例外をキャッチし、自動的にSentryサーバーに例外イベントを送信。
  - 本番環境でのサーバークラッシュ、Stripe署名検証失敗、Gemini APIのクォータ切れなどをリアルタイムで自動検知・通知します。

### 2. 自動メール通知 (Resend)
- **構成**: `resend` SDKを使用したトランザクショナルメール送信。
- **アーキテクチャ**:
  - Stripeの Webhook イベントを受け取り、プラン変更完了時に自動でメールを送信します。
  - **決済・アップグレード完了時**: プレミアムプランの特典紹介を含むウェルカムメールの送信。
  - **サブスクリプション解約完了時**: 解約処理が正常に行われたことを通知するメールの送信。
  - 送信先アドレスは、Stripe Checkoutに入力された最新のクライアントアドレス、またはStripe APIから直接取得した顧客データを元にします。

### 3. APIセキュリティ強化 (Firestore レートリミット)
- **構成**: Firestoreの書き込み履歴を活用したスライディングウィンドウ型レートリミッター。
- **アーキテクチャ**:
  - 不正スクリプトやDDoS攻撃、二重クリック防止のため、各重要APIルートでアクセス制限を実施。
  - **Checkout API**: 1分間に最大3回まで。
  - **AI Scan API**: 1分間に最大5回、1日に最大30回まで。
  - **Events API (保存・削除)**: 1分間に最大15回、1日に最大100回まで。
  - 制限を超過した場合は自動的に `HTTP 429 Too Many Requests` エラーを返却し、バックエンドのシステム負荷を防御します。

### 4. カレンダーUIの改善 (レスポンシブ刷新 & 週・月表示切り替え)
- **構成**: Tailwind CSS + Lucide React によるフルレスポンシブ設計。
- **機能**:
  - PC、スマホ、タブレットに完全対応したレイアウト。
  - 月カレンダーと週カレンダー（現在の選択日の週を7日分表示）の表示切り替えトグルの追加。
  - 予定の有無と予定登録者のカラー（パパ・ママ・子供など）に合わせた美しく整列するカラーバッジ。
  - スキャン実行時の高級感あふれるローディング・スケルトンアニメーション。

### 5. Google カレンダー双方向同期 (OAuth 2.0)
- **構成**: `googleapis` (Google Calendar API v3) + OAuth 2.0 認証フロー。
- **アーキテクチャ**:
  - アプリから「Google連携」ボタンを押し、Googleカレンダーの編集権限を承認。
  - 認可コードから取得したリフレッシュトークン等の認証情報を、セキュアなAES-256-CBC方式で暗号化してFirestore (`users/${userId}/security/googleOAuth`) に格納。
  - ユーザーがアプリ上でおたよりをスキャンして予定が保存、または手動で予定を作成・変更・削除した際、自動的にバックエンドでトークンの有効期限をチェック（必要に応じてリフレッシュトークンで自動更新）し、ユーザーのGoogleカレンダーに予定をシームレスかつリアルタイムに同期します。
  - 予定には `googleEventId` が紐づけられ、編集・削除時も同一イベントが追跡更新されます。

## 🔑 Google OAuth 2.0 設定手順 (管理者向け)

カレンダー連携機能を使用するためには、Google Cloud ConsoleでのOAuthクライアントIDの設定が必要です。

1. **Google Cloud Console** にログインし、新しいプロジェクトを作成または既存のプロジェクトを選択します。
2. **「APIとサービス」 > 「ライブラリ」** から、**Google Calendar API** を検索し、「有効にする」をクリックします。
3. **「OAuth同意画面」** を設定します：
   - **User Type**: **「外部 (External)」** を選択します（「内部（Internal）」に設定したままだと、一般のGoogleアカウントでログインしようとした際「組織内でのみ利用可能です」とエラーになります）。
   - スコープに `.../auth/calendar.events` (カレンダー the events) を追加します。
   - 公開ステータスが「テスト中」の間は、下部にある **「テストユーザー (Test users)」** にログインテストを行いたいGoogleアカウントのアドレスを明示的に追加・登録しておく必要があります。
4. **「認証情報」 > 「認証情報を作成」 > 「OAuthクライアントID」** をクリックします：
   - アプリケーションの種類: Webアプリケーション
   - **承認されたリダイレクトURI** に、以下の本番コールバックURLを追加します：
     `https://<your-vercel-domain>.vercel.app/api/auth/google-calendar/callback`
     （ローカル開発時は `http://localhost:3000/api/auth/google-calendar/callback` も併記可能）
5. 生成された **クライアントID** と **クライアントシークレット** を、環境変数 `GOOGLE_CLIENT_ID` および `GOOGLE_CLIENT_SECRET` に設定します。
6. 暗号化用のキーとして、`ENCRYPTION_KEY` に十分な長さ（32文字以上推奨）のランダムな文字列を設定してください。

## 💰 マネタイズ設定手順 (Stripe & AdSense 管理者向け)

本アプリの収益化機能（サブスクリプションおよび広告配信）を正常に動作させるため、以下の設定を行います。

### 1. Stripe サブスクリプション商品 (Price ID) の設定
本番環境でアドホックなインライン価格生成を避け、Stripe ダッシュボードで固定登録された商品（月額480円プランなど）に紐付けるため、Price ID を定義します。

1. **Stripe ダッシュボード**（本番環境または開発用テスト環境）にログインします。
2. **「商品」 > 「商品を追加」** から以下を設定して保存します：
   - 商品名: `おたよりカレンダー プレミアムプラン`
   - 料金形態: `継続（サブスクリプション）`
   - 請求周期: `月次`
   - 価格: `480 JPY`
3. 作成された商品の詳細画面で、**「API ID」（例: `price_1Qxxxx...`）** をコピーします。
4. この ID を環境変数 `NEXT_PUBLIC_STRIPE_PRICE_ID` に設定します。設定されている場合、アプリは最優先でこの Price ID を使用してセッションを生成します。（未設定の場合はインラインで価格が自動生成されるフォールバックが働きます）

### 2. Google AdSense の設定
ユーザー（非プレミアム）に広告を表示し、最適に配信するための設定です。

1. **Google AdSense** にログインし、広告を作成（ディスプレイ広告など）して**広告ユニットのスロットID**を取得します。
2. アカウントの**パブリッシャーID**（例: `ca-pub-5461809032953003`）を環境変数 `NEXT_PUBLIC_ADSENSE_CLIENT_ID` に設定します。
3. アプリ上の広告は `AdBanner` コンポーネントを通じて自動レンダリングされます：
   - **配置箇所**: カレンダー下部、サイドバー下部、およびAIスキャン完了結果画面。
   - **非表示ロジック**: ユーザーがプレミアムプランを購読している場合（Firestore上で `plan` が `premium` の場合）、`AdBanner` コンポーネントは完全に `null` を返してレンダリングを回避します。
   - **スクリプトの最適化**: 広告読み込み用のGoogle AdSenseスクリプトは、Next.jsの `next/script` を通じて `strategy="afterInteractive"` で非同期的に非ブロッキングロードされます。

### 3. Firebase Web Push通知 (FCM) の VAPID 設定
予定の3日前・前日の通知（リマインド）機能を有効にするための設定です。

1. **Firebase コンソール** にログインし、対象プロジェクトを開きます。
2. 左上の歯車マーク ⚙ ➔ **「プロジェクトの設定」** を開きます。
3. **「Cloud Messaging」** タブをクリックします。
4. 下部にある **「ウェブ設定 (Web configuration)」** セクションの **「ウェブプッシュ証明書 (Web Push certificates)」** に移動します。
5. 表示されている **「鍵ペア (Key pair)」** の文字列（非常に長い英数字）をコピーします（※まだ作成されていない場合は「鍵ペアの生成」ボタンをクリックして新規発行してください）。
6. コピーしたキーを、環境変数 **`NEXT_PUBLIC_FIREBASE_VAPID_KEY`** に設定します（Vercelの環境変数および `.env.local` への登録が必要です）。

### 4. Google Analytics 4 (GA4) の設定
ユーザーの重要アクション（AIスキャン開始/成功、決済アップグレードクリック、通知ON、カレンダー連携）を追跡・効果測定するための設定です。

1. **Google Analytics** にログインし、新しいGA4プロパティを作成します。
2. データストリームの追加で「ウェブ」を選択し、本番環境のドメイン（例: `otayori-calendar-owfg.vercel.app`）を登録します。
3. 生成された **「測定ID」（例: `G-XXXXXXXXXX`）** をコピーします。
4. コピーした測定IDを、環境変数 **`NEXT_PUBLIC_GA_ID`** に設定します（Vercelの環境変数および `.env.local` への登録が必要です）。

### 5. PWA (iOS通知最適化) および Google 審査対策の法的ページ設定
iOS (Safari) における通知の許可基準と、Google OAuth 審査を通過するための法的要件に関する設定です。

1. **iOS 向け PWA 通知ガイド**:
   - iOS の仕様上、プッシュ通知を有効にするには「ホーム画面に追加」されてスタンドアロンモードで起動されている必要があります。
   - iOS 且つ非スタンドアロンモードで通知設定を行おうとした場合、自動的に「ホーム画面に追加」の手順を解説するガイダンスモーダルがポップアップ表示されます。
2. **法的ページの設定と Google OAuth 審査**:
   - Google OAuth の検証審査を通過するため、`/terms` (利用規約) および `/privacy` (プライバシーポリシー) の静的ページが自動生成され、アプリの全画面フッターにリンクが設置されています。
   - [privacy/page.tsx](file:///c:/dev/otayori-calender/otayori-calendar/src/app/privacy/page.tsx) には、Google審査基準である **Google APIユーザーデータ限定使用に関する開示 (Limited Use Disclosure)** が明記されています。

### 6. iOS / Safari 向けの互換性およびデバッグ対策
iOS (Safari) 環境で発生しやすいエラーや挙動不整合に対する対策です。

1. **日付パースの堅牢化 (Safari対策)**:
   - Safari の古い・厳格なパーサー仕様に対応するため、日付文字列（"YYYY-MM-DD"形式）のハイフンを自動でスラッシュ（"YYYY/MM/DD"形式）に置換してからパースする `safeParseDate` ヘルパーを適用しています。
2. **Stripe決済画面リダイレクト時のセキュリティブロック回避**:
   - 非同期処理後に `window.location.href` を書き換える際、Safariやアプリ内ブラウザ（WebView）がポップアップブロックやセキュリティ違反と誤検知してクラッシュするのを防ぐため、`try-catch` と `window.location.assign`、さらには `window.open` による多重フォールバック構造を実装しています。
3. **データ読み込み失敗時のエラー解説強化**:
   - Firebase Authentication のログイン後に Firestore からの読み込みで `permission-denied` (セキュリティルール拒否) が発生した際、単に「データの読み込みに失敗しました」と出すのではなく、Firebaseコンソール上でのルールの公開適用漏れを疑う具体的なアドバイスを表示し、トラブルシューティングを円滑にします。

### 7. Firebase Auth と Firestore 状態の同期タイムラグ対策
ログイン成功直後に発生しやすいアクセス権限エラー（Permission Denied）への対策です。

1. **認証監視とデータフェッチの分離**:
   - `onAuthStateChanged` の中での直接のデータフェッチ（`getDocs`, `getDoc`）を廃止し、独立した `[user, isAuthLoading]` 依存 of `useEffect` に処理を移行しました。これにより、Firebase SDK が内部的な認証トークンのセットアップを完全に完了したタイミングでクエリが実行され、同期ズレによるエラーが解消されます。
2. **FCMトークン自動同期の遅延ガード**:
   - ログイン直後の FCM トークン取得・保存（`getAndStoreToken`）において、Firestore への書き込みを行う前に 150ms のディレイを挟み、さらに `auth.currentUser` の認証確立状態をダブルチェックする防護ロジックを追加しました。

### 8. プロダクトグロース向け新機能
家族間でのカレンダー共有、過去スキャンの履歴閲覧、および実績の動的SNSシェアのための機能群です。

1. **家族シェア（カレンダー連携）機能**:
   - カレンダーデータストアを `groups/${groupId}/events` に移行・共通化しました。
   - 各ユーザーは固有の招待コード（`inviteCode`）を持ちます。UIからパートナーのコードを入力して連携すると、双方向でリアルタイムに同一のカレンダー同期（書き込み・読み込み）が実行されます。
   - 連携開始時に、それまで自分が登録した予定もパートナーの共有グループに自動マージされる親切設計です。
2. **おたよりスキャン履歴ダッシュボード**:
   - アプリケーション画面の「履歴一覧」タブから、過去にスキャンしたおたよりプリントの画像サムネイルと、自動抽出された予定の内容を一覧表示できます。
   - カード内の詳細ボタンから、既存の予定詳細モーダルを開いて確認・編集・削除・ICSエクスポートが可能です。
3. **動的OGP画像生成API (`/api/og`)**:
   - Next.js の `next/og` (`@vercel/og` Edge runtime) を活用した画像生成APIを新設しました。
   - `count` クエリパラメータ（例: `/api/og?count=12`）を付与してアクセスすると、「AIでおたよりの予定を 12件 自動化しました！」というスタイリッシュなブランドカラーのアイキャッチ画像を動的に描画して出力します。
